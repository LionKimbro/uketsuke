The one-turn receptionist machine.

OWNS
  resolving one uketsuke turn
  identifying and performing the absolute highest-priority available
  receptionist action
  the priority order among pending receptionist actions
  globally inspectable facts about the most recent turn

READS
  the active job, when one exists
  the inbox, when there is no active job

CALLS
  the machine responsible for the selected receptionist action

MAY SAFELY ASSUME
  that startup initialization has completed
  that the configured directory tree exists

ENSURES
  that do_tick performs at most one meaningful receptionist action
  that a True-returning do_tick performs the absolute highest-priority
    action available at that time, when there is one
  that do_tick returns True while the host should call it again
  that do_tick returns False when runtime is done
  that the runtime state panel describes the most recent turn

DOES NOT OWN
  the host program's forever loop
  scheduling, sleeping, or process lifetime
  durable job-record transitions
  filesystem primitives
  the host's interpretation of an opaque request or the work it performs

g = {
    "operation": None,
    "quit": False,
}


panel = {
    "turn-count": 0,
    "last-operation": None,
    "last-result": None,
    "last-error": None,
    "quit": False,
}


def do_tick():
    return False immediately if the system is in the quit state

    panel["turn-count"] += 1
    clear_the_observation_facts_for_this_new_turn()

    g["operation"] = identify_what_needs_to_be_done()

    perform g["operation"]
    set panel["last-operation"] to the descriptive name of g["operation"]

    return True if we continue, False if the system is now in the quit state


def clear_the_observation_facts_for_this_new_turn():
    panel["last-operation"] = None
    panel["last-result"] = None
    panel["last-error"] = None


def identify_what_needs_to_be_done():
    ask jobs to read the current active job, if there is one

    if there is an active job:
        return the lifecycle-required operation for its status
        follow JOB-LIFECYCLE.txt for the status map
        follow DEAD-LETTER.txt when that operation is dead-letter transfer

    if there is an inbox message available to claim:
        return "claim-inbox-request"

    return "idle"


def perform_operation_claiming_an_inbox_request():
    follow the planned claim procedure in CLAIMING.txt
    set the operation's readable identity to "claim-inbox-request"


def transition_to_the_quit_state():
    Set g["quit"] to True, set panel["quit"] to true.

PRIORITY ORDER

  1. perform the lifecycle-required action for the active job, if there
     is one
  2. otherwise claim an inbox request, if there is one
  3. otherwise idle
